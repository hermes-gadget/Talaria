# Talaria full codebase audit — 2026-08-04

Audited revision: `5cf5389c1ed367434ba25a9fd872cbafe6f43f78` on `audit/next-roadmap`.

## Scope and method

This was a read-only audit of the complete Android application and its assurance/release material: all Kotlin, resources, assets, and the manifest under `app/src/main`; all 68 unit-test files, eight JSON fixtures, and the single instrumentation test; Gradle/version-catalog/wrapper/R8 configuration; `.github/workflows`; `ROADMAP.md`; root documentation; `docs/API.md`; and every existing file in `review-reports`. Historical reports were used only as leads and every retained claim was checked against current code.

The repository contains 51,283 lines of production Kotlin. The largest concentration points are `ChatViewModel.kt` (3,261 lines), `ChatScreen.kt` (1,509), `KanbanScreen.kt` (1,212), `HermesRepository.kt` (1,152), and `HermesApi.kt` (1,075). The security pass accounted for all 334 authoritative review-inventory items. Binary assets were classified by role; the Gradle wrapper JAR was present and reviewed as a binary artifact rather than decompiled.

One permitted build was run:

```text
JAVA_HOME=/home/ben/java ANDROID_HOME=/home/ben/android-sdk \
./gradlew :app:testDebugUnitTest --no-daemon --max-workers=1

BUILD SUCCESSFUL in 28s
240 tests, 0 failures, 0 errors
```

The unit task was restored from Gradle cache, but its XML result set was present and summed independently. No emulator, device, lint, release build, tag, or application-source modification was used.

## Executive verdict

No Critical issue was found. Fourteen High findings remain, led by an approval UI that can silently grant a broader server choice, incomplete exact-origin/legacy cleartext consent, cross-origin credential-bootstrap redirects, connection-scope races, incomplete WebSocket bounds, secure-store failure behavior, and a release workflow that can publish without its validation job or fail-closed signature verification.

The overnight wave delivered substantial foundations: authenticated car-host policy, immutable snapshots, bounded containers, atomic transcript replacement, and a generation-safe PTY supervisor are real code. It did not complete most roadmap acceptance contracts. R0.6 is functionally implemented; R0.1–R0.5 and R0.7/R0.9–R0.11 remain Partial, while R0.8 is Not Done.

The fast unit vocabulary is broad, but assurance at the boundaries is shallow: there is one instrumentation test, no Compose behavior suite, no Room migration harness, no secure-store corruption/Keystore test, no real car-service caller test, and no end-to-end worker or PTY recovery test.

## Rejected or narrowed security candidates

- No generic REST SSRF/injection was retained: dashboard origin is operator-configured by design, URL validation rejects non-HTTP(S), embedded credentials, query and fragments (`ConnectionRepository.kt:71-82`), and Retrofit encodes path/query values. Bootstrap redirects are reported separately because they carry credential bodies across the saved origin.
- No main-client redirect credential leak was retained: network interceptors re-check origin and cleartext on every redirect/retry (`HermesClientFactory.kt:123-131`), and the cookie jar returns matching cookies only.
- No current release allow-all car-host vulnerability was retained: debug alone uses allow-all and a second session authorizer denies untrusted transcript/actions. The remaining observed-host workflow/test gap is compatibility and assurance.
- HTTP logging is BASIC with auth/session header redaction; WebSocket clients intentionally have no logger. No secret-body logging finding was retained.
- `AnsiStripper.Stream` stores enum state, not an unbounded pending escape buffer. The actual issues are pre-parser frame bounds and Terminal's stateless second pass.
