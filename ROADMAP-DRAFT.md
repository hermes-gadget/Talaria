### Batch 01 — production files 1–10 (2,067 lines)

Read in full: MainActivity.kt, TalariaApp.kt, car/{CarConversationNotifier,CarHostSecurity,CarSessionsRepository,SessionListScreen,TalariaCarService}.kt, core/data/db/{Daos,Entities,TalariaDatabase}.kt.

- **B01 / Medium / Crash risk:** `app/src/main/java/com/hermesgadget/talaria/MainActivity.kt:187` calls `Uri.getQueryParameter()` on an externally supplied ACTION_VIEW URI without checking `isHierarchical`. An explicit launch with `talaria:opaque` reaches this before the navigation parser. Fix: validate action/scheme/hierarchy before query access; add an intent regression test.
- **B02 / High / Security boundary:** `car/SessionListScreen.kt:371–378` publishes conversation notifications after an asynchronous load without rechecking current host trust. The trust listener (74–80) does not cancel loads or clear notifications. `CarConversationNotifier.kt:118–150` always attaches a reply action, including for manually enrolled read-only hosts. Follow up through NotificationActionReceiver/ReplyWorker before finalizing the bypass finding. Fix direction: propagate car authorization to reply actions and generation-guard/revoke in-flight reads and posted notifications.
- **F01 / Medium / Incomplete car experience:** `car/SessionListScreen.kt:133–134,357–385` only fetches conversations initially or after a local action; there is no refresh/timer/event subscription, so replies from the agent or other clients remain stale while the screen stays open. `onMarkAsRead()` at 305/328 is an explicit no-op. Fix: lifecycle-bound refresh/event invalidation and a meaningful local/server read policy.
- **P01 / Medium / Startup I/O:** `TalariaApp.kt:38–42` performs cache cleanup and recursive ops-import deletion synchronously during Application.onCreate. Cost grows with leftovers and delays every cold launch. Fix: perform cleanup on an I/O executor with ownership coordination before consumers use affected files.
- **Verification notes:** database reconciliation is transactional and prunes messages plus organization metadata; connection/profile keys and bounded delete batches exist. These are implemented protections, not missing work. No existing project documentation was used as evidence.

### Batch 02 — production files 11–20 (in progress)

- **B03 / Medium / Filter corruption:** `core/data/db/Daos.kt:94–96` clears both labelId and groupId when either references a deleted collection. Deleting a label unexpectedly removes a still-valid group constraint (and vice versa). Fix: independent CASE expressions; test a saved filter containing both references.
- **B04 / High / Stale security scope:** `core/data/prefs/SecureConnectionStore.kt:446–466` clears profiles/active ID after a runtime credential read failure but never clears `_scope` or advances scope generation. Consumers of the scope flow can retain the previous credential-bearing snapshot until another mutation occurs. Fix: publish an invalidated null scope atomically with the failure state; verify cancellation of scope consumers.
- **B05 / Medium / Broken corruption handling:** `core/data/prefs/CarHostTrustStore.kt:288–292` performs encrypted `getString` outside the catch; runtime decryption failures escape into car/template/UI callers. Invalid JSON silently becomes an empty Available store, and retry (132–138) returns true whenever prefs is non-null without validating content. Fix: catch authenticated reads, publish typed corruption, validate on retry, and prevent silent overwrite of damaged records.
- **B06 / Medium / Consent race:** `core/data/repo/ConnectionRepository.kt:211–232` reads a snapshot then unconditionally upserts it when recording cleartext consent. A concurrent edit/deletion can be overwritten or resurrected, including stale secrets. Fix: store-level exact-snapshot compare-and-set covering the whole consent operation.
- **Q01 / Low / Incomplete local purge:** `core/data/prefs/SettingsStore.kt:211–220` claims to remove every scoped key but omits `cache_pending_pairing_`, `sync_*`, and hashed agent notification bookkeeping (225–264,310–320). Fix: centralize scoped key ownership and purge all namespaces, with a connection identity in currently hashed lanes.

Batch 02 complete: files 11–20 read in full (CarHostTrustStore through SessionOrganizationRepository).

- **B07 / High / Hung loads:** `core/data/repo/ResponseCache.kt:171–202` creates a parentless CompletableDeferred for followers, but leader cancellation rethrows at 185–186 without completing/cancelling that deferred. Joined callers wait indefinitely after the leader screen leaves. Fix: complete the gate exceptionally on every exit; test leader cancellation with a still-live follower.
- **B08 / High / Cache invalidation races:** `ResponseCache.kt:158–180,193–196` allows post-invalidation callers to join pre-invalidation work; generation comparison and put are separate critical sections, allowing invalidation between them and stale repopulation. Prefix/predicate invalidation (107–119) misses a first fetch whose key has no generation entry. Fix: version in-flight identities and perform stamp-check/store under the same lock; do not join old generations.
- **B09 / High / Destructive reconciliation from incomplete payloads:** `core/data/repo/HermesRepository.kt:345–361` silently drops undecodable object rows, treats unknown shapes as empty, and treats a bare array page length as the total. `fetchSessionsForReconciliation` (270–312) can then mark that partial result complete and delete cached sessions, messages, favorites, and links (247–261). Fix: track decode completeness separately; never prune on malformed/ambiguous payloads; require trustworthy pagination completion.
- **B10 / Medium / Transcript rollback race:** `HermesRepository.kt:387–427` has no per-session ordering/mutex around concurrent fetch, DB replace, and fingerprint publication. An older slow response can replace a newer completed transcript and stamp its fingerprint. Fix: serialize per scope/session or compare request/revision generations before cache commit.
- **P02 / Medium / Cache budget does not bound retained payloads:** `ResponseCache.kt:238–247` assigns any DTO 256 bytes and clamps aggregate collections/maps to the whole 8 MiB budget. A huge collection can therefore fit by definition, and DTO strings are not counted. `keyGenerations` also grows without eviction. Fix: real payload-aware weights, reject oversize entries, and bound/remove generation bookkeeping safely.
- **Q02 / Medium / Non-atomic remote editing:** `HermesRepository.kt:1131–1147` compares a preflight read then writes without an expected version/hash sent to the server. A host edit between those requests is overwritten. Fix: server conditional write/ETag; if unsupported describe the limitation and provide diff/conflict recovery.

### Batch 03 — production files 21–30 (in progress)

- **B11 / Medium / Activity scope attribution:** `core/lifecycle/HermesForegroundObserver.kt:104–105` obtains the current connection when consuming an event rather than using the event's immutable origin scope. Queued events may be attributed to a newly selected connection. It also starts collection only on process onStart, so connecting for the first time while foreground may leave Activity unsubscribed. Follow up against the event client's scope/restart behavior.

Batch 03 complete: files 21–30 read in full (TranscriptReconciliation through HermesEventClient; all 1,343 event-client lines and 1,114 API lines included).

- **B12 / High / Multi-profile transport interference:** `core/network/HermesClientFactory.kt:164–174` evicts and cancels every other snapshot for the same connection ID, including snapshots differing only in managementProfile. Background profile/tab clients compete with the foreground profile and cancel each other's calls/sockets. Fix: permit concurrent profile bundles for the same valid transport/credential generation and evict only obsolete credentials/configuration; synchronize eviction with construction. Verify against ProfileRegistry and Chat background-tab code.
- **B13 / Medium / Malformed frame handling:** `core/network/HermesEventClient.kt:723–744,1049–1071,1174–1176` catches JSON syntax parsing but performs `jsonPrimitive` casts and typed classification outside the catch. Valid JSON such as an object-valued id/method/choice throws instead of producing a contained protocol error. Fix: safe type accessors and a full classifier boundary, with malformed-shape tests.
- **B14 / High / Streaming loss (pending consumer confirmation):** `HermesEventClient.kt:974–983` classifies MessageDelta as replaceable with one coalescing key per session, although its field is a delta chunk. Slow consumers can lose all but the latest queued chunk. Fix: concatenate bounded deltas or signal authoritative reconciliation rather than replacing incremental text.
- **B15 / Medium / Header validation:** `core/network/AuthInterceptor.kt:111–117` removes C0/DEL but retains non-ASCII characters which OkHttp's strict header API can reject. AuthInterceptor creates the header outside a conversion-to-IOException boundary. Fix: validate header-compatible credential characters on entry and convert invalid stored credentials into a typed recoverable error; verify installed OkHttp behavior.
- **Q03 / Medium / Monolithic transport/API layer:** `core/network/HermesApi.kt:109` exposes 1,000+ lines of unrelated feature endpoints and the repository is 1,256 lines. Several routes have duplicate typed/raw forms. Fix: split cohesive API/repository interfaces while preserving shared snapshot enforcement and one tested contract per endpoint.
- **P03 / Medium / Repeated credential decryption:** `AuthInterceptor.kt:41,90,98`, `HermesClientFactory.kt:230–233`, and snapshot capture repeatedly decrypt the same saved secret set per request. Fix: publish immutable authenticated snapshots with a generation stamp after store mutations and check that stamp on each hop.

### Batch 04 — production files 31–40 complete

Read in full: HermesWebSocketUrlBuilder, JsonConfig, NativeOidcLogin, ProfileQueryInterceptor, ProfileRegistry, PtyPromptDelivery, PtyTransportSupervisor, PtyWebSocketSession, ResponseBodyLimitInterceptor, SessionCookieJar.

- **B16 / High / Path-prefixed deployments lose profile/auth policy:** `core/network/ProfileQueryInterceptor.kt:41–46` only recognizes paths beginning `/api/`, while accepted base URLs and Retrofit preserve a path prefix (`HermesClientFactory.kt:262`). With `https://host/hermes`, many calls omit profile injection and can act on the server default profile. Auth suppression/bootstrap checks (`ConnectionSnapshot.kt:196`, `AuthInterceptor.kt:120–124`) and endpoint response budgets (`ResponseBodyLimitInterceptor.kt:167–177`) also assume root paths. Fix: derive the route relative to the captured base path consistently and test prefixed REST/WS/OIDC/mutation paths.
- **B17 / High / False prompt-delivery success:** `core/network/PtyPromptDelivery.kt:133–162,218–242,248–253` accepts any sidecar message boundary without session/delivery correlation, or terminal output containing generic words such as “agent” or “running.” Buffered startup output or an earlier turn can satisfy this immediately after queuing input. Fix: explicit correlated server acceptance receipt; until supported preserve uncertain delivery rather than claiming acknowledgement from generic terminal text.
- **B18 / Medium / Registry reset/refresh race:** `core/network/ProfileRegistry.kt:62–66,108–189` reset does not coordinate with the refresh mutex or invalidate an in-flight generation. A finishing old-connection refresh can repopulate the process-wide registry after reset; updates use read/copy/write and can overwrite concurrent stream transitions. Fix: instance/scope ownership, generation validation, atomic updates, and loading cleanup on cancellation. Validate whether callers always cancel before reset.
- **P04 / Medium / Oversized-frame protection happens after allocation:** `core/network/PtyWebSocketSession.kt:175–190` and `HermesEventClient.kt:552–566` check size only inside OkHttp onMessage, which receives an already-materialized complete message. This caps retained application payloads but does not prevent transport-level OOM from a huge/fragmented message. Fix: transport reader budget or trusted proxy cap; document and test the actual boundary.
- **Q04 / Low / Inconsistent permanent-close policy:** PTY terminal codes (`PtyTransportSupervisor.kt:57`) omit 1009 while the sidecar includes it; oversized PTY messages therefore trigger repeated reconnects up to exhaustion. Fix: share close classification and treat message-too-large as a user-visible terminal protocol failure.

### Batch 05 — production files 41–50 complete

Read in full: SnapshotCredentialHelpers, WebSocketFrameBudget, WsAuthHelper, AgentAlertDispatcher, AgentNotificationPolicy, AgentTaskNotificationService, NotificationActionReceiver, NotificationChannels, QuietHours, ReplyPayloadBuilder.

- **B19 / High / Token refresh cancels its own request:** `core/network/SnapshotCredentialHelpers.kt:251–262` invokes onTokensRotated from the AuthInterceptor refresh path; `HermesClientFactory.kt:44–46,154–158,177–181` cancels all calls for that connection, including the original request currently trying to use the new token. Fix: retire bundles for future acquisition without cancelling the successful refreshing call, and coordinate consumers with the new snapshot.
- **B20 / High / Loopback token discovery invalidates its caller:** `core/network/WsAuthHelper.kt:124–129` persists a newly discovered token while returning auth to a caller whose REST/WebSocket client is still bound to the old snapshot. AuthInterceptor's next current-snapshot check rejects that client. This needs verification across initial connect/retry paths; fix direction: return refreshed snapshot + auth as one atomic result and build the socket from it.
- **B21 / Medium / Notification reply can crash before error handling:** `core/notifications/NotificationActionReceiver.kt:65–68` constructs the spill directory and writes the reply file before entering try. `ReplyPayloadBuilder.kt:27–40` throws on mkdir/write failures (e.g. disk full), escaping BroadcastReceiver.onReceive; disk writes also run on main. - **B22 / Medium / Dead foreground monitor:** `core/notifications/AgentTaskNotificationService.kt:368–369` only recognizes a few string forms as terminal, while HermesEventClient emits “WebSocket closed permanently (...)” for permanent close codes. Such a watcher never stops and the ongoing service stays alive. Fix: typed terminal transport state and terminal-close tests.
- **B23 / High / Monitor snapshot validation compares the wrong snapshot:** `AgentTaskNotificationService.kt:215–221` resolves a new saved snapshot and compares it to the current saved one, never comparing `runtime.client.fixedSnapshot`. Same-ID URL/credential edits leave the stale runtime installed; secret-only changes may not emit either observed flow at 94. Fix: observe connection scope generation and compare/rebind the actual runtime snapshot.
- **U01 / Medium / Notification localization gaps:** `AgentNotificationPolicy.kt:60,82,109,132–137`, `NotificationChannels.kt:45–50,103`, and `TalariaNotifier.kt:82,111–114,131–150` contain user-visible English and count-dependent text outside resources/plurals. Fix: localized rendering at the Android boundary with plural resources.

### Batch 09 — files 81–90 (share persistence and complete chat UI/runtime)

- **B33 — High — Wrong-session discovery.** `feature/chat/ChatViewModel.kt:1355–1363,3122–3136`: a newly sending tab claims the newest session absent from its baseline, with no channel/request correlation. Two new tabs or an unrelated Discord/CLI session can swap ownership; later approvals, images and history target that unrelated session. Fix: obtain a durable session ID from the creating channel; never infer identity from recency.
- **B34 — High — Multi-profile runtime support contradicts client lifetime.** `ChatViewModel.kt:508–517,660–684` deliberately retains old-profile tabs, while `HermesClientFactory.kt:164–181` evicts/cancels other snapshots for the same connection (B12). `ChatViewModel.kt:1705` renames through the active-profile repository, and branch completion at 1758/1812 opens the child with whichever snapshot is now active. Fix: compare against each tab's profile and only an authoritative complete list.
- **B36 — High — Old REST history can finish a new turn.** `ChatViewModel.kt:3220–3233`: the comment promises a superset check, but implementation accepts any nonempty unequal transcript and treats any trailing assistant as the new reply. - **B38 — Medium — Queued message is removed before transport acceptance.** `ChatViewModel.kt:2338–2341,2453–2456` dequeues before sending; a rejected socket send only sets an error and loses the queued text. Fix: retain/reinsert the item until accepted, with a delivery ID and explicit unknown-delivery state.
- **B39 — Medium — Draft persistence uses foreground scope instead of tab scope.** `ChatViewModel.kt:2139–2157` persists any tab's edits under currentDraftPersistenceScope; old-profile tabs remain selectable. Multiple tabs also share one persisted draft and restore it to the first tab (729–746). Fix: persist per immutable connection/profile/session or tab identity and flush pending edits on lifecycle exit.
- **B40 — Medium — Fresh image cannot be removed before session assignment.** `ChatViewModel.kt:2270–2272`: both attachedSessionId and sessionId are null, so equality reports an unattached image as already staged. Fix: require a nonnull attachedSessionId before comparing.
- **B14 confirmed:** `ChatViewModel.kt:3354–3362` appends MessageDelta chunks and uses that buffer when MessageComplete has no text (3493–3494); replacing deltas in the ingress demonstrably loses content.
- **S03 — High — Server dictation bypasses voice-cloud preference and can retarget audio.** `ChatViewModel.kt:2578–2581,2729–2742` always prefers server STT; the Android recognizer cloud flag does not gate it. If the originating tab is removed while encoding, `tabSnapshot(tabId) ?: clientFactory.snapshot()` can send its recording to the newly active server before the scope check after the network call. Fix: capture the originating snapshot before recording; require explicit server-STT consent and check current scope before upload, with no fallback to another connection.
- **S04 — Medium — Deny-only approval choices gain an invented approve option.** `feature/chat/ApprovalChoicePolicy.kt:33–39`, `ChatScreen.kt:322–328`, `ChatViewModel.kt:2521–2522`: filtering deny before the empty-list fallback treats an explicit deny-only list like no choices and allows once. - **P05 — High — Eager sockets for every unfinished session.** `ChatViewModel.kt:1157–1227` auto-opens a PTY and two sidecar sockets for every nonautomation session lacking end metadata, even idle history. There is no tab/socket cap; each tab also owns several coroutines. Fix: keep merged session metadata cheap, connect visible/actively watched sessions on demand, and bound concurrency.
- **Q07 — High — ChatViewModel combines unrelated ownership responsibilities.** `ChatViewModel.kt:330–3633` owns sockets/retries, session identity, registry, persistence, media encoding, microphone, commands, approvals and presentation state; direct global AppContainer access bypasses injected repositories. Extract independently testable session-runtime, delivery, transcript, draft and dictation components with explicit lifetimes.
- **U04 — Medium — Transcript scroll and keyboard navigation override user position.** `ChatScreen.kt` auto-scroll effect (earlier file segment) scrolls on transcript changes regardless of reading position; 1175–1180 captures all Up/Down keys as history, including multiline cursor navigation. Fix: follow only when already near the bottom; use history at composer boundaries or an explicit shortcut.
- **U05 — Low — Small interactive targets.** `ChatScreen.kt:1557–1562` makes the 18dp tab-close icon directly clickable; attachment close uses 32dp (1136–1140). Fix: give controls at least 48dp interactive bounds with descriptive semantics.
